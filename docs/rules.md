# Task Manager authorization rules

This file is the product-level source of truth for authorization behavior. API
policies, tests, and frontend visibility must agree with this matrix. The
backend is authoritative; hiding a frontend control is not authorization.

## Roles

- **Owner:** the project creator. Every project has exactly one owner.
- **Admin:** a project administrator appointed within that project.
- **Member:** a regular project participant.
- **Outsider:** an authenticated user with no membership in the project.
- **Anonymous:** a caller without valid authentication.

Roles are project-specific. A user's role in one project grants no permission
in another project.

## Permission matrix

| Action | Owner | Admin | Member | Outsider | Anonymous |
|---|---:|---:|---:|---:|---:|
| Create a project | Yes | Yes | Yes | Yes | No |
| List own projects | Yes | Yes | Yes | Yes | No |
| List project members | Yes | Yes | Yes | No | No |
| Add a member | Yes | Yes | No | No | No |
| Remove a member | Yes | Yes | No | No | No |
| Remove an admin | Yes | No | No | No | No |
| Remove the owner | Never | Never | Never | Never | Never |
| Leave a project | Not supported | Not supported | Not supported | N/A | N/A |
| Create or assign a task | Yes | Yes | No | No | No |
| List project tasks | All | All | Assigned tasks only | No | No |
| Update status of an assigned task | Yes | Yes | Yes | No | No |
| Update status of an unassigned/other member's task | Yes | Yes | No | No | No |
| Delete a task | Yes | Yes | No | No | No |

## Invariants

1. The project creator is stored as both `projects.owner_id` and an `owner`
   membership. Project creation writes both records in one transaction.
2. The owner membership cannot be removed or demoted. Ownership transfer and
   leave-project flows are outside the current scope.
3. An admin may remove a member, but not another admin or the owner.
4. The owner may remove admins and members.
5. An assignee must be a current member of the task's project.
6. A non-member receives `403 Forbidden` when requesting project members or
   tasks. Member task visibility is enforced in the SQL query.
7. Status values are `todo`, `in_progress`, and `done`. The UI displays these
   as “To Do”, “In Progress”, and “Done”.
8. Task status updates are allowed only for the assigned member or a project
   owner/admin. This is an explicit product decision.

## Authentication and CSRF

- JWT access tokens are stored only in `Secure`, `HttpOnly` cookies in
  production, never in local storage.
- Cookie-authenticated `POST`, `PUT`, `PATCH`, and `DELETE` requests require the
  `X-CSRF-TOKEN` header generated by Flask-JWT-Extended's double-submit cookie
  protection.
- The React API client sends credentials on every API request and attaches the
  CSRF header to unsafe methods.
- Authentication answers who the caller is. The membership policy still runs
  for every project-scoped operation.
